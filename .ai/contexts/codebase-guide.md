## §1. Repository Layout

Canonical layout (directories are created as the project grows; absence of a
directory means that concern does not exist yet):

| Path | Purpose | Notes |
| --- | --- | --- |
| `go.mod`, `go.sum` | Module definition and dependency checksums | Source of truth for the Go version and dependencies |
| `cmd/<binary>/` | Executable entrypoints, one directory per binary | `main` package only; keep thin |
| `internal/` | Private packages, not importable by other modules | Default home for implementation code |
| `pkg/` | Public, importable packages | Only for code with a deliberate external API contract |
| `testdata/` | Fixtures read by tests | Ignored by the Go toolchain for builds |
| `.ai/contexts/` | Authoritative agent guides (this file lives here) | Single source of truth for policies |
| `.ai/plans/` | Working plans produced by agents | Scratch space, not policy |
| `.claude/`, `.codex/`, `.gemini/`, `.opencode/` | Per-tool adapters | `.claude/` is canonical; others generated |
| `.github/` | Issue templates, PR template, workflows | GitHub-specific |
| `scripts/` | Repository automation | Includes `sync-ai-config.sh` |

**Verify the live layout instead of trusting this table**:
```bash
git ls-files | awk -F/ 'NF>1{print $1"/"} NF==1{print $1}' | sort -u
```

## §2. Package Architecture

Dependency direction is one-way:

```
cmd/<binary>          (wiring, flag parsing, exit codes)
      │
      ▼
internal/<feature>    (business logic, no I/O concerns leaking upward)
      │
      ▼
internal/<primitive>  (shared low-level helpers)
```

**Rules**:
- `cmd/` may import `internal/` and `pkg/`; nothing may import `cmd/`.
- `internal/` must not import `cmd/`.
- `pkg/` must not import `internal/` — an exported API cannot depend on private
  code that consumers cannot see or replace.
- No import cycles; `go build ./...` enforces this, but design to avoid them.

**Query the real dependency graph**:
```bash
go list -deps ./... | grep "$(head -1 go.mod | awk '{print $2}')"
go mod graph                       # module-level edges
```

## §3. Core Capabilities

### §3.1 Quick Reference: "Where is X?"

| Looking for | Look in | Query |
| --- | --- | --- |
| A binary's entrypoint | `cmd/<name>/main.go` | `ls cmd/` |
| A feature's logic | `internal/<feature>/` | `rg -l '<symbol>' internal/` |
| A publicly exported API | `pkg/` | `go doc ./pkg/...` |
| A test for a file `x.go` | `x_test.go` next to it | `fd 'x_test.go'` |
| A fixture | nearest `testdata/` | `find . -type d -name testdata` |
| Where a symbol is defined | anywhere | `rg -n 'func <Name>\|type <Name>'` |
| Where a symbol is used | anywhere | `rg -n '\b<Name>\b'` |

### §3.2 Adding a new capability

1. Decide visibility: private → `internal/<feature>/`; public API → `pkg/<feature>/`.
2. Create the package directory; the package name matches the directory name.
3. Add `<feature>.go` plus `<feature>_test.go` in the same package.
4. Wire it from `cmd/<binary>/main.go` if it needs an entrypoint.
5. Run `build-test-runner build` then `build-test-runner test`.

## §4. File Naming Conventions

| Kind | Pattern | Example |
| --- | --- | --- |
| Implementation | `lower_snake.go` (short, no stutter) | `internal/store/store.go` |
| Test | `<file>_test.go` | `internal/store/store_test.go` |
| Example test | `example_test.go` | `pkg/api/example_test.go` |
| Benchmark | in `<file>_test.go`, `func BenchmarkX` | — |
| Platform-specific | `<file>_<GOOS>.go` | `fs_linux.go` |
| Build-tagged | `//go:build <tag>` first line | `//go:build integration` |
| Generated | header `// Code generated by ... DO NOT EDIT.` | `zz_generated.go` |

**Anti-stutter rule**: a package named `store` exports `store.New`, not
`store.NewStore`.

## §5. Architecture Principles

1. **`internal/` by default.** Promote to `pkg/` only when an external consumer
   genuinely exists; promotion is a one-way API commitment.
2. **Accept interfaces, return structs.** Define interfaces in the consuming
   package, not alongside the implementation.
3. **Errors are values.** Wrap with `fmt.Errorf("...: %w", err)`; inspect with
   `errors.Is` / `errors.As`. Never discard an error with `_`.
4. **`context.Context` first.** Any function that blocks, does I/O, or may be
   cancelled takes `ctx context.Context` as its first parameter.
5. **No global mutable state.** Pass dependencies explicitly; `init()` is for
   registration only.
6. **Thin `cmd/`.** `main` parses flags, builds dependencies, and calls into a
   `run(ctx) error`; all logic is testable below it.

## §6. Troubleshooting

| Symptom | Root cause | Fix |
| --- | --- | --- |
| `use of internal package not allowed` | Importing `internal/` from outside the module subtree | Move the package or promote to `pkg/` |
| `import cycle not allowed` | Bidirectional package dependency | Extract the shared type into a lower-level package |
| `no required module provides package` | Missing dependency | `go mod tidy` |
| `./...` matches nothing | cwd is outside the module | `cd "$(git rev-parse --show-toplevel)"` |
| Package name ≠ directory name | Manual rename | Rename the package clause to match the directory |
